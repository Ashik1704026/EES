ASSIGNMENT MODULE

Purpose:
Assign room population to exits using shortest-path costs while respecting
exit quotas. This implementation uses the greedy fallback described in the spec.

Pseudocode:

1. Compute total_people = sum(initial_people of all active rooms).
2. Compute total_exit_rate = sum(exit_service_rate of all active exits).
3. For each exit x:
   3.1 quota[x] = round(total_people * rate[x] / total_exit_rate)
4. Fix rounding mismatch by adding the remaining difference to the last exit.
5. Build candidate list from all reachable routes:
   candidate = (room_id, exit_id, route_cost)
6. Sort candidates by:
   6.1 lower route_cost first
   6.2 smaller room_id first
   6.3 smaller exit_id first
7. remaining_room_people[room] = room.initial_people
8. exit_load[exit] = 0
9. First greedy pass:
   For each candidate (r, x, c) in sorted order:
   9.1 room_left = remaining_room_people[r]
   9.2 exit_left = quota[x] - exit_load[x]
   9.3 If room_left <= 0 or exit_left <= 0, continue
   9.4 assigned = min(room_left, exit_left)
   9.5 assignment[r, x] += assigned
   9.6 remaining_room_people[r] -= assigned
   9.7 exit_load[x] += assigned
10. Second fill pass:
    For each room r with remaining_room_people[r] > 0:
    10.1 Find the first reachable candidate for that room in sorted order
    10.2 Assign all leftover people to that exit, even if quota is exceeded
11. Output:
    - assignments
    - exit_quotas
    - exit_loads
    - total_assigned
    - unassigned_people
    - success/failure status

Theoretical Complexity:

- Let:
  R = number of active rooms
  X = number of active exits
  K = number of reachable room-exit pairs, where K <= R * X

- Time:
  O(K log K) for sorting the candidate list
  O(K) for the first greedy pass
  O(R * K) worst-case for the second fill pass in this implementation

  Overall worst-case:
  O(K log K + R * K)

- Space:
  O(K + R + X)

Empirical Complexity On Your Machine:

Machine:
- Intel Core i9 9th Gen
- 16 GB DDR4
- C++ optimized build (-O2)

Measured average runtime per call:

- EASY   : 0.0013 ms
- MEDIUM : 0.0028 ms
- HARD   : 0.0042 ms

Empirical interpretation:

- Runtime is almost flat on the provided scenarios because K is still very small.
- Even the HARD scenario has only a limited number of room-exit combinations,
  so sorting and greedy assignment are negligible in practice.
- This module is faster than both routing and simulation on the tested inputs.

Practical Takeaway:

- Theory depends mostly on the number of reachable room-exit pairs.
- Empirically, the assignment step is tiny for these building sizes.
- If the project later replaces greedy assignment with full min-cost flow,
  the asymptotic and measured cost will increase.
